# 板式吸光度发布系统

面向实验室数据员：上传孔位图与读板仪读数，系统按“扣空白 → 检查复孔 → 检查阳性对照下限”的顺序给出**整板**是否可发布，并把每次发布绑定到具体的输入版本，供追溯与纠错。

## 功能

- **导入**：新建板，上传孔位图（CSV/TSV，长表或网格）与孔位读数（长表或数值网格），一次上传后自动计算。
- **计算规则**
  - 每个孔先减**空白孔均值**（空白孔本身不参与样本）；
  - 每个样本必须**恰好两枚复孔**且两孔都有读数；
  - 阳性对照孔扣除空白后的**均值必须 ≥ 登记下限**（默认 `0.5`，环境变量 `PLATE_QC_POSITIVE_MIN` 可改）；
  - 空白孔、阳性对照孔在孔位图登记后必须都有读数；
  - 以上任一不满足 → **整板不发布**，并逐条列出原因。
- **发布版与过期**：发布版是“孔位图版本 + 读数版本 + 质控结论 + 样本结果”的不可变快照。
  - 纠正孔位图或补传读数会生成新版本，并在同一事务内把当前发布版标记为**过期**；
  - 过期版**仍然可查看**，且始终展示它当时绑定的输入版本与原始文件；
  - 只有**重算成功**才启用新版（旧版转为“已被替换”）；重算失败只记录一次失败尝试，过期旧版保留，不会启用半成品。
- **并发一致性**：所有写操作使用 SQLite `BEGIN IMMEDIATE`（单写者串行），版本号由事务内分配；报告读取在单个读事务中完成。发布记录只引用具体版本 id，因此并发上传、重算与查询不会混用不同版本的孔位图、读数或质控结论。
- **页面**：板列表、板详情（当前版状态、上传/纠错、重算、版本历史、原始文件下载）、发布版报告（质控逐项结果、参与孔位、样本均值）。

## 上样链核对（移液来源追溯）

数据员怀疑机器人把样本转错孔时，用“上样链核对”还原读板孔液的来历：

- **选择**：源板（登记样本编号的板）与待核板（要还原的板），上传机器人转移日志 CSV/TSV。日志按 `operation` 顺序列出 `source_plate, source_well, target_plate, target_well`，允许样本先经过任意多块中间板；源板、待核板及所有中间板都必须已有孔位图。
- **追溯语义**：源板的样本孔是追溯起点（编号登记在孔位图上）；待核板和中间板从空孔开始，只能通过日志获得来源。
  - 每次转移读取源孔**当时**的内容。**事后向中间孔补加样本，不会改写此前的转移**，物理上也不应该改写。
  - 转移会把源孔中的全部来源链复制到目标孔；一个孔混入不同样本后，该孔及**所有下游孔**都标为混样并列出每条链的路径。
  - 还原结果与待核板登记编号逐孔对照：一致 / 错位（追溯到别的样本）/ 缺失（没有来源）/ 混样，并展示完整路径与相关操作序号。
  - **结构性问题**（重复操作序号、无效孔位、读空孔取源、向空白/对照/未登记孔加样、中间板缺孔位图、日志未引用所选板）使整次核对**失败**：记录失败尝试、不发布结果、不给出可信结论。
- **版本与过期**：
  - 每次上传转移日志生成不可变版本，并立即把该源板/待核板对的当前核对结果标为**过期**（仍可查看，仍展示其原绑定输入）。
  - **任意参与板**（源板、待核板或中间板）的孔位图更正，都会让引用该旧版本的所有核对过期；转移日志替换同理。
  - 只有**重算产生完整可信结果**才启用新版本（旧版转为“已被替换”）；核对失败只记录失败尝试，过期旧版保留可查。
- **并发一致性**：一次核对在单个 `BEGIN IMMEDIATE` 事务内读取最新已提交的转移日志版本和全部参与板孔位图版本，并把每个板的孔位图版本 id 与日志版本 id 一起写入核对记录。并发上传/重算只会发布基于同一批已提交输入的完整结果，不会把 A 时刻的日志与 B 时刻的孔位图混在一起。

### 转移日志格式

```csv
operation,source_plate,source_well,target_plate,target_well
1,源板,A1,中间板,A1
2,源板,A2,中间板,B1
3,中间板,A1,待核板,A1
4,中间板,B1,待核板,A2
```

板名必须与系统中的板名称完全一致；孔位形如 `A1`–`P24`。也接受中文表头（操作序号、源板、源板孔位、目标板、目标板孔位）。示例：`samples/transfer_chain.csv`（正常多跳）、`samples/transfer_mix.csv`（上游混样扩散到下游）。

## 运行（Docker Compose）

```bash
docker compose up --build
# 打开 http://localhost:8000
```

数据（SQLite 与上传原件）保存在命名卷 `plate-data`。可调整的环境变量：

| 变量 | 默认 | 说明 |
| --- | --- | --- |
| `PLATE_DATA_DIR` | `/data`（镜像内） | 数据目录 |
| `PLATE_QC_POSITIVE_MIN` | `0.5` | 阳性对照扣除空白后的均值下限 |
| `PLATE_MAX_UPLOAD_BYTES` | `10485760` | 单文件大小上限 |

## 本地开发

```bash
python3 -m venv .venv && . .venv/bin/activate
pip install -r requirements-dev.txt
uvicorn app.main:app --reload
pytest -q
```

## 输入格式

孔位图（长表）：

```csv
well,role,sample_id
A1,blank,
A2,sample,S1
A3,sample,S1
A4,positive_control,
```

孔位图（网格）：首行是空单元格 + 列号，首列是行字母，单元格填样本编号、`BLANK`/`空白`、`PC`/`阳性对照`，空或 `-` 表示未用。

读数（长表 `well,absorbance` 或同样布局的数值网格）：

```csv
well,absorbance
A1,0.100
A2,0.600
```

编码支持 UTF-8（含 BOM）与 GB18030；分隔符自动识别逗号、分号或制表符。表头也接受中文名（孔位/样本/吸光度等）。示例见 `samples/`。

结构性问题（重复孔位、无效孔位、非数字读数、缺表头等）会**直接拒绝**，不会生成版本；实验性问题（复孔数、质控下限等）会保存为版本并在计算阶段导致整板不发布，便于纠错后重算。

## 主要 HTTP 接口

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/healthz` | 健康检查 |
| GET/POST | `/api/plates` | 列出 / 创建板 |
| GET | `/api/plates/{id}` | 板快照（当前发布版、历史、版本列表） |
| POST | `/api/plates/{id}/uploads` | multipart：`map_file`、`readings_file`、`note` |
| POST | `/api/plates/{id}/recompute` | 按最新版本重算 |
| GET | `/api/plates/{id}/publications/{pub}` | 单个发布版报告（含绑定输入） |
| GET | `/api/chains` | 每对源板/待核板的最新核对（含当前有效结果） |
| POST | `/api/chains` | multipart：`source_plate_id`、`target_plate_id`、`log_file`、`note` |
| GET | `/api/chains/{id}` | 核对记录（状态、绑定版本、逐孔还原、路径、问题） |
| POST | `/api/chains/{id}/recompute` | 按最新日志与全部参与板孔位图重算 |
| GET | `/api/chains/{id}/log` | 下载该核对绑定版本的转移日志原件 |

网页入口：`/chains`（核对列表与新建）、`/chains/new`、`/chains/{id}`（结论详情）。板详情页也会列出该板参与的全部有效核对及其角色（源板/中间板/待核板）。

## 设计边界

- 单进程/单机 SQLite；并发写通过 `BEGIN IMMEDIATE` 串行，未做多节点部署。
- 孔位图是 CSV/TSV 文本，不是图片；没有 OCR 或图像标注界面。
- 不提供用户登录与权限控制，也未实现发布版/核对结果的手工撤回（只做自动过期与替换）。
- 上样链核对按“体积来源”建模：只看转移日志中登记的转移，不建模残留体积、洗针或取样比例；部分体积混合也按“混样”处理，不计算混合比例。
- 转移日志中的板名需与系统中的板名精确匹配（区分大小写）；重命名板不会自动更新历史核对，历史核对仍按原板 id 与孔位图版本追溯。
